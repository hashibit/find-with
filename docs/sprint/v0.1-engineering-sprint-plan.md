## 一、工程组织原则

### 1.1 仓库布局
```
findwith/
├── proto/              # buf 单源，CI 跑 lint + breaking + generate
├── backend/            # FastAPI + worker + alembic（U-01 ownership）
├── extension/          # MV3 Chrome 扩展
├── web/                # Next.js 14 官网
├── docs/{prd,tech,sprint,runbook}
├── scripts/{dr,smoke,seed}
└── .github/workflows/  # 四个 stack 各自 lint+test，proto 变更触发全量
```

### 1.2 分支与 release
- `main` 永远绿；feature 分支 PR 合入；`release/*` 切自 main 跑 e2e
- 扩展走 Chrome Web Store 4-7 天审核 → 提前打 RC tag；后端/官网 Render/Vercel 直接 deploy
- 每个 sprint 末打 `sprint-N` tag，方便回滚

### 1.3 验证分层（每个任务必须填够）
| 层 | 工具 | 何时 |
|---|---|---|
| **静态** | ruff + mypy + tsc + buf lint + alembic check | 每次 push pre-commit + CI |
| **单测** | pytest（backend）、vitest（ext / web） | CI must pass |
| **集成** | testcontainers PG + Redis + minio + mailpit；FakeProvider 替换 LLM | CI nightly + sprint 末 |
| **E2E** | playwright（web + 扩展 headless via puppeteer-stream）、自录 LinkedIn/Gmail HTML fixture | sprint 末 |
| **手动 smoke** | 列入每个 sprint DoD 的 5 步剧本 | sprint 验收会 |
| **golden 回归** | 5 份脱敏简历 / 5 份 JD / 3 封邮件 / PDF ATS 解析 | CI must pass |
| **性能 / 成本** | k6 + LLM cost 报表（`llm.cost_usd_per_user_per_day`）周巡检 | 每周一 |

### 1.4 Done 定义（DoD，所有 sprint 通用）
1. 代码合 main，CI 全绿
2. 该 sprint 任务的**自动验证步骤**全部跑过（pytest/vitest/playwright + golden）
3. **手动 smoke 剧本**走完一遍并截图存 `docs/sprint/evidence/<sprint>/`
4. Telemetry 看板有该 sprint 引入的事件 ≥ 1 条真实数据（dev 环境）
5. 文档（API doc / runbook）更新 PR 同 sprint 合入

## 三、各 Sprint 详细

每个 sprint 节包含：**目标 / 输入 / 任务 / 验证 / DoD / 风险**。验证步骤与任务一一对应，不允许"做完了但没验过"。

### P0-S1（W1）：仓库 / proto / Postgres / 观测骨架

**目标**：四仓 monorepo 可 build，proto 生成代码可 import，PG/Redis/R2 本地起得来，Sentry/OTel 跑通。

**输入**：v0.1-product-design §1, §3, §10；v0.1-website-design §1, §8

**任务**
1. monorepo 初始化（pnpm workspace + uv + buf）；CI 模板（lint/test 四个 stack 并行）
2. `proto/findwith/{common,profile,jobs,conversation,agent,tool,tailoring,apply,followup,iam,quota,telemetry,billing}/v1/*.proto` 全量落地
3. `buf generate` → Python (Pydantic v2) + TS + JSON Schema；artifact cache
4. backend FastAPI skeleton：`/v1/health`、`/v1/ready`（DB+Redis+LLM HEAD 探活）
5. alembic 初始化 + `iam_users`、`iam_settings`、`outbox_events`（含 `consumer_group`，**关闭 U-02 一半**）、`idempotency_keys`、`telemetry_events`（按月分区）、`billing_subscriptions`（**关闭 U-01**：alembic 在 backend 仓库内单源）
6. `docker-compose.dev.yml`：postgres15+pgvector / redis / minio / mailpit
7. Sentry + OpenTelemetry 接入（env 控制 DSN）
8. `scripts/dr/restore-from-r2.sh` 骨架 + nightly dump cron 配置（Render cron job）—— **关闭 U-07 一半**
9. `CONTRIBUTING.md` 写进 proto 演进顺序约束（**关闭 U-09**）
10. **字段级加密启动序列**（关闭 U-10）：
    - 选 pgcrypto AES-256；DEK 存 Render env var（v0.1 accepted risk，§12.1）；KEK 走 Doppler agent 启动注入
    - 实现 `app/security/crypto.py`：`encrypt_field(plaintext) -> bytes` / `decrypt_field(ct) -> str`
    - alembic migration：标记需要加密的列（resume bytes、email body、material.raw_text）为 `bytea`
    - 启动期验证 KEK 可解 DEK，否则进程 fail-fast

**验证**
- `make ci` 一键跑全 stack lint+test 全绿
- `buf lint && buf breaking --against=.git#branch=main` 通过
- `docker compose up -d && curl localhost:8000/v1/ready` 返回 `{db:ok, redis:ok, llm:ok}`
- `alembic upgrade head` 后 `psql -c "\dt"` 能看到 §五 列出的全部表；encrypted 列声明全是 `bytea`，无 `text`
- Sentry dev 环境 throw 一次异常能看到面板上报；OTel trace 能在 console exporter 打出
- `scripts/dr/restore-from-r2.sh --dry-run` 输出预期步骤
- pytest：encrypt → write → read → decrypt round-trip 单测
- 启动 fail-fast：故意把 KEK 改错 → 进程 1s 内退出 + Sentry 上报

**DoD**：以上验证 + DoD 通用 5 条 + smoke：从空仓库到 `make ci && docker compose up && curl /v1/ready` < 10 min；加密 round-trip 跑过 + fail-fast 演示一次

**风险**
- buf 生成 Python pydantic 的插件 `protoc-gen-python-betterproto2` 对某些 oneof/well-known types 兼容性不稳 → 备选 `betterproto` v1 stable + 手 patch
- pgvector ivfflat 索引在 Render 默认 PG 镜像里不一定开 → P0 必须在 Render staging 上验证

### P0-S2（W2）：Auth / IAM / Outbox publisher / API gateway 规约

**目标**：Clerk JWT 校验通；扩展端能拿到 token 调 `/v1/me/entitlements`；outbox 双消费组跑得起来。

**任务**
1. Clerk 接入：webhook `/v1/iam/webhooks/clerk`（user.created/deleted）+ JWT 中间件（jose JWK cache）
2. `iam_users` lazy sync（webhook 后到时不覆盖已写值）
3. `/v1/me/entitlements`、`/v1/me/quota` 实现（先返回 mock FREE）
4. **U-03 关闭**：`POST /v1/iam/auth/exchange`（auth_code → JWT）+ Redis 一次性 code 存储 + IP 绑定
5. Outbox publisher 进程：`backend/workers/outbox_publisher.py`，`SKIP LOCKED` + `consumer_group` 路由（**关闭 U-02 全部**）
6. Idempotency middleware（`Idempotency-Key` header → Redis 24h）
7. 全局错误：`application/problem+json` + `findwith.common.v1.Error`
8. Rate limit middleware（token bucket key=user+endpoint，存 Redis）

**验证**
- pytest：JWT 中间件单测（伪造签名 401 / 过期 401 / 合法 200）
- pytest：webhook 重放幂等（同一 `user.created` 事件两次只插一行）
- pytest：outbox publisher 集成测试 — 写 10 条不同 consumer_group → 各自只拿到自己的
- 手动：开 ngrok → Clerk dev webhook → 注册新用户 → DB `iam_users` 多一行
- 手动：`curl -H "Idempotency-Key: x" POST /v1/iam/auth/exchange` 同 code 两次 → 第二次 409
- 单测：rate limit 第 7 次 `/v1/conversations/.../messages` 返回 429
- **U-03 验证**：扩展模拟客户端 — sendMessage 传 code → exchange 拿 JWT → 用 JWT 调 `/v1/me/entitlements` 200；同 code 第二次 exchange 401

**DoD**：通用 + 手动 smoke：本地起 backend，Clerk 注册一个用户，扩展骨架（mock）拿到 JWT 调通

**风险**：Clerk JWT JWK rotate 时 cache miss 处理 → 单测覆盖；ngrok 域名漂移 → CI 不依赖 ngrok，本地用 mock webhook
