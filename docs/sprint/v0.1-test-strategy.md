## 一、テスト分層方針

```
┌─────────────────────────────────────────────────────────────────┐
│                     テストピラミッド                              │
├─────────────────────────────────────────────────────────────────┤
│  E2E Tests  (少量のコアパスのみ)                                 │
│  ─────────  ⬤                                                      │
│                                                                   │
│  Integration Tests (API/バックエンドサービス)                   │
│  ───────────────  ⬤诚意                                         │
│                                                                   │
│  Unit Tests (CU/WPバックエンドロジック)                          │
│  ───────────  ⬤诚意诚意诚意诚意诚意诚意诚意诚                     │
└─────────────────────────────────────────────────────────────────┘
```

### 原則
- **CU**: unit tests - 各サービスのロジックを単体でテスト
- **WP**: worker/process テスト - BullMQ キュー処理など
- **E2E**: クリティカルなユーザー旅程のみ (onboarding → job tailoring → export)

```typescript
// test/unit/tailoring/tailoring.service.spec.ts
describe('TailoringService', () => {
  let service: TailoringService;
  let resumeRepo: MockRepository<TailoringResume>;
  let snapshotRepo: MockRepository<TailoringSnapshot>;
  let quotaService: QuotaService;

  beforeEach(async () => {
    resumeRepo = createMockRepository();
    snapshotRepo = createMockRepository();
    quotaService = { consumeOnExport: vi.fn() } as any;

    const module = await Test.createTestingModule({
      providers: [
        TailoringService,
        { provide: getRepositoryToken(TailoringResume), useValue: resumeRepo },
        { provide: getRepositoryToken(TailoringSnapshot), useValue: snapshotRepo },
        { provide: QuotaService, useValue: quotaService },
      ],
    }).compile();

    service = module.get<TailoringService>(TailoringService);
  });

  describe('start', () => {
    it('create tailoring resume record');
    it('enqueue tailor job to BullMQ');
  });

  describe('findOne', () => {
    it('return tailored resume');
    it('throw NotFoundException if not found');
    it('throw ForbiddenException if unauthorized');
  });

  describe('editBullet', () => {
    it('update bullet text');
    it('set source to USER_EDITED');
    it('throw NotFoundException if bullet not found');
  });

  describe('exportPlainText', () => {
    it('return plain text format');
    it('consume quota via QuotaService');
    it('throw ForbiddenException when quota exhausted');
    it('idempotent - does not double consume');
  });
});
```

## 五、カバレッジ目標

| モジュール | 行カバレッジ | 分岐カバレッジ | スターター |
|----------|------------|-------------|----------|
| backend-ts | > 80% | > 75% | 核心サービス全カバー |
| extension | > 70% | > 65% | DOM 依存部分は 60% |
| web | > 60% | > 55% | Next.js コンポーネント段階的追加 |

### メモ
- **100% カバレッジは目標しない** - テストコストとリターンのバランス
- **重要なのはテスト質** - 正しい振る舞いを検証できれば十分
- **カバレッジは指標一つ** - コードの変更後、テストが反応することを確認
